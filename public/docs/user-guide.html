How to update data on GitHub — recommended path

Pages serves the built site; vacancy data comes from committed CSV (Excel is never read in the browser).

  1. Clone or pull: git clone https://github.com/mag-services/psc-pvp-dashboard.git and open the repo folder (where package.json lives).
  2. Edit Ministries_PVP_Clean.xlsx, worksheet data, save.
  3. Place the workbook at repo root next to package.json, or (if the app lives in a subfolder) one level above that app folder.
  4. Regenerate CSV: 
    pip install pandas openpyxl
npm run generate-data
    Writes public/data/ministries_pvp.csv.
  5. Commit and push to main: 
    git add public/data/ministries_pvp.csv
git commit -m "Update ministry vacancy CSV"
git push origin main
  6. Open Actions on GitHub → wait until the Pages workflow succeeds.
  7. Reload mag-services.github.io/psc-pvp-dashboard/ with hard-refresh (Ctrl+F5).
CI: npm run build:pages builds the static app only unless your workflow explicitly runs Excel → CSV. Committing updated ministries_pvp.csv is the simplest way to refresh the live data.

Optional: store Excel on GitHub

You can commit Ministries_PVP_Clean.xlsx at the repo root for backup or future automation—but the site reads public/data/ministries_pvp.csv until you regenerate and commit CSV (or automate that in Actions).

Update steps (local)

1. Edit the workbook

Open Ministries_PVP_Clean.xlsx, edit the data sheet, save.

2. Regenerate the CSV

From the dashboard folder (alongside package.json):

npm run generate-data

Requires Python 3, pandas, and an Excel engine (e.g. openpyxl):

pip install pandas openpyxl

Writes public/data/ministries_pvp.csv. If the workbook is missing, place Ministries_PVP_Clean.xlsx beside package.json or in the parent folder (see script error message).

3. Check locally

npm install
npm run dev

Or full build + preview (npm run build runs generate-data first; npm run build:pages does not):

npm run build
npm run preview
GitHub Actions: Typical CI uses npm run build:pages (TypeScript + Vite only). Push an updated ministries_pvp.csv so the live site shows new data unless your workflow regenerates CSV.

4. Push to GitHub

  1. Commit the updated ministries_pvp.csv (and the .xlsx if your team keeps it in Git).
  2. Push to main (or your deploy branch).
  3. Wait for GitHub Pages / Actions to finish.

How the app loads data

Static React + Vite app. It fetches ./data/ministries_pvp.csv at runtime — it does not read Excel in the browser. Routes: #/executive, #/ministry, #/recruitment.
